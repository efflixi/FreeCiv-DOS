DOS 6.22 boot and runtime steps for the Freeciv DOS port project

1. Boot DOS from DOS622.img (A:). Attach dos-vm/DOS622_VHD.img as C:.
   dos-vm/DOS622_VHD.vhd is a separate older image; do not use or synchronize it.

2. The working raw hard disk has an MBR partition table and an active primary
   type-06 FAT16 partition at LBA 63 (byte offset 32256), length 524288 sectors.
   Its BIOS geometry is 521 cylinders / 16 heads / 63 sectors, without translation.
   The disk is 268886016 bytes; the FAT16 volume inside it is 268435456 bytes.
   The former unpartitioned FAT16 image was readable by mtools but was NOT exposed
   as C: by actual DOS. A filesystem image alone is not a DOS hard-disk layout.

3. From the project directory, boot the tested Pentium / 16 MB configuration:
   qemu-system-i386 \
     -machine pc -accel tcg -m 16 -cpu pentium -vga std \
     -drive file=DOS622.img,format=raw,if=floppy \
     -drive file=dos-vm/DOS622_VHD.img,format=raw,if=none,id=drivec \
     -device ide-hd,drive=drivec,bus=ide.0,unit=0,cyls=521,heads=16,secs=63,bios-chs-trans=none \
     -boot a -nic none \
     -monitor stdio

   The graphical QEMU window shows the DOS screen; the terminal is the QEMU
   monitor, not a DOS input console. Use the window keyboard for DOS commands.
   Stop QEMU using "quit" at its monitor before accessing images with host tools.
   Equivalent headless tests use QMP keyboard/mouse injection and live VGA
   captures. BIOS text-screen capture alone does not validate graphics.

4. Startup stops at C:\>, without launching a game or demo. Run:
   ver
   dir C:\
   echo write-test>C:\FREECIV\WRITE.TXT
   type C:\FREECIV\WRITE.TXT

   Actual tests reached MS-DOS Version 6.22 and read back a DOS-created C: file.
   If C: is unavailable, the floppy startup reports a partition/geometry error
   and stays at A:\> for recovery. Do not attempt Freeciv until C: is accessible.

5. C: root retains only IO.SYS, MSDOS.SYS, COMMAND.COM, DRVSPACE.BIN,
   AUTOEXEC.BAT, CONFIG.SYS, and DOS/FREECIV/ARCHIVE directories.
   - C:\DOS contains DOS utilities/support files.
   - C:\FREECIV\FREECIV.EXE is the verified builds/phase7-dos/civclient.exe.
   - C:\FREECIV\CWSDPMI.EXE and CWSDPMI.DOC are unchanged CWSDPMI r7 files.
   - C:\FREECIV\RTCHECK.EXE is the separate runtime diagnostic.
   - C:\FREECIV\VBECHECK.EXE is the separate actual VBE display diagnostic.
   - C:\FREECIV\RNDCHECK.EXE is the separate primitive/font/dirty-render diagnostic.
   - C:\FREECIV\MAPCHECK.EXE is the separate actual-state map/HUD diagnostic.
   - C:\FREECIV\INPUTCHK.EXE is the separate production-loop input diagnostic.
   - C:\FREECIV\GFX8 contains selected Trident 8.3 graphics/specs/manifests
     and four default .RUL aliases for MAPCHECK/INPUTCHK fixtures only,
     NOT a complete game install.
   - C:\FREECIV\DATA\RUNTIME.DAT is its test marker, NOT game resources.
   - C:\ARCHIVE\OLDCLI.EXE preserves the previous installed client unchanged.
     PHASE2.EXE preserves the Phase 2 candidate installed during Phase 3.
     PHASE4.EXE preserves the preceding Phase 4 candidate unchanged.
     PHASE5.EXE preserves the preceding Phase 5 candidate unchanged.
     PHASE6.EXE preserves the preceding Phase 6 candidate unchanged.
     FCSTUB.COM, AUTOOLD.BAT, and IMPORT.TMP preserve the older demo/startup.
   - Optional C:\DOS\CTMOUSE.EXE/CTMOUSE.TXT/CTMLIC.TXT/CTMSRC.ZIP preserve
     the unchanged GPL driver, documentation, license and full source package.

6. Host startup sources are dos-vm/BOOT_A.BAT and dos-vm/AUTOEXEC.BAT.
   Floppy AUTOEXEC checks C:\COMMAND.COM before handing off to C:\AUTOEXEC.BAT.
   C: startup sets PATH=C:\DOS;C:\FREECIV, COMSPEC=C:\COMMAND.COM, and C:\.
   No DPMI host or game is loaded automatically by AUTOEXEC.

   Booting A: reads A:\CONFIG.SYS, not C:\CONFIG.SYS. The tested A: configuration
   is COUNTRY=001 with the floppy COUNTRY.SYS; it loads neither HIMEM.SYS nor
   EMM386. C:\CONFIG.SYS is retained but is not applied by the AUTOEXEC handoff.
   CWSDPMI works in this tested minimal configuration. Other memory-manager
   combinations are untested; do not prescribe them as prerequisites.

7. Test the normal client:
   cd \FREECIV
   set HOME=C:\FREECIV
   CWSDPMI -s-
   FREECIV --version
   CWSDPMI -s-
   FREECIV

   --version prints "Freeciv version 1.14.1 gui-dos-vbe". CWSDPMI can auto-load
   from the executable directory, but repeat -s- before each no-paging process.
   Normal startup opens a persistent pregame interface using real VBE/input.
   F1/F2/F3 open Help/Options/Commands; Tab/Shift-Tab and Enter navigate widgets.
   Esc cancels the current dialog/action first. From home/the map,
   Q/Ctrl-Q/Alt-F4 requests quit with
   Cancel selected: Enter cancels, Tab/Enter confirms and returns zero to DOS.
   New/load-game setup is explicitly unavailable. Options are in-memory only;
   no session is created, no current player is renamed, and no save is written.
   Audio is explicitly disabled. The installed program is not yet playable.
   HOME avoids the original options subsystem's missing-home warning; without
   it, the warning is surfaced rather than silently hidden.
   FREECIV -a fails nonzero with an actionable unavailable-autoconnect message.
   Upstream --version writes to stderr, so >VERSION.TXT alone captures no text.
   Without a DPMI host the DJGPP loader reports "Load error: no DPMI".

8. For the verified runtime-only test, explicitly disable paging:
   C:\FREECIV\CWSDPMI -s-
   C:\FREECIV\RTCHECK --log C:\FREECIV\RUNTIME.LOG

   The diagnostic verifies DOS/DPMI, a read/written 1 MiB heap, real-mode INT 21h,
   a 512-byte conventional transfer buffer, executable-relative marker lookup,
   and real isolated-engine join/request/reset/teardown. It stays at READY until
   Q is pressed, then returns successfully to DOS. --batch skips that input wait.
   READY is diagnostic readiness only: no VBE/video mapping, actual rulesets,
   game map/AI turn, graphics, sound, or production event loop is exercised.

   CWSDPMI without -p unloads after ONE protected-mode application exits.
   Repeat "CWSDPMI -s-" before EACH no-paging test; running FREECIV --version
   between those commands consumes the one-process host. If paging is desired,
   use "CWSDPMI -sC:\FREECIV\CWSDPMI.SWP" before the application. Its unmodified
   auto-load default instead uses C:\CWSDPMI.SWP; do not mistake swap-assisted
   operation for a successful 16 MB physical-memory fit test.

9. Validate working-directory-independent diagnostic lookup:
   A:
   C:\FREECIV\RTCHECK --batch --log C:\FREECIV\FROMA.LOG
   C:
   cd \
   RTCHECK --batch --log C:\FREECIV\ROOT.LOG
   cd \FREECIV
   RTCHECK --batch --log C:\FREECIV\FROMDIR.LOG

   All three were actually executed successfully. The normal --version path
   also works from A:, C:\, and the install directory. Actual game resource
   discovery remains pending DOS filename/resource packaging.
   An explicit missing --fixture path fails without READY and returns nonzero.
   With 2 MB RAM and paging disabled, the diagnostic loader reports
   "Load error: no DPMI memory" and returns nonzero to the DOS prompt.
   This negative test is not a lower supported hardware target.

    mcopy -o -i dos-vm/DOS622_VHD.img@@32256 builds/phase7-dos/INPUTCHK.EXE ::/FREECIV/INPUTCHK.EXE
    mcopy -o -i dos-vm/DOS622_VHD.img@@32256 builds/phase6-dos/MAPCHECK.EXE ::/FREECIV/MAPCHECK.EXE
    mcopy -o -i dos-vm/DOS622_VHD.img@@32256 builds/phase5-dos/RNDCHECK.EXE ::/FREECIV/RNDCHECK.EXE
    mcopy -o -i dos-vm/DOS622_VHD.img@@32256 builds/phase4-dos/VBECHECK.EXE ::/FREECIV/VBECHECK.EXE
    mcopy -o -i dos-vm/DOS622_VHD.img@@32256 builds/phase3-runtime/RTCHECK.EXE ::/FREECIV/RTCHECK.EXE
    mcopy -o -i dos-vm/DOS622_VHD.img@@32256 runtime/cwsdpmi-r7/bin/CWSDPMI.EXE ::/FREECIV/CWSDPMI.EXE

    mcopy -o -i dos-vm/DOS622_VHD.img@@32256 dos-vm/RUNTIME.DAT ::/FREECIV/DATA/RUNTIME.DAT

    These install directories already exist on the published working image.
    Never run mtools or replace images while a VM is using them. sfdisk --verify
    checks the partition table, not FAT; FAT checking needs an extracted
    524288-sector partition (starting at byte 32256) and fsck.fat -n.
    dos-vm/partition_drive.py wraps only an UNPARTITIONED FAT16 source into a NEW
    output file; do not run it on the already partitioned working image.

13. Real VBE display diagnostic (not the game):
    Use QEMU's standard VGA adapter (add "-vga std" to step 3). The tested
    display contract is VESA 2.0+ RGB565 LFB plus BIOS 4F04 state save/restore
    and the host's 0508 managed-device-mapping extension. Banked-only hardware
    is unsupported. QEMU cirrus fails clearly because its requested BIOS
    state service is unavailable; VESA presence alone is insufficient.

    For 640x480:
    C:\FREECIV\CWSDPMI -s-
    C:\FREECIV\VBECHECK --640 --log C:\FREECIV\VBE640.LOG

    For preferred 800x600 (falls back to validated 640x480 if unavailable):
    C:\FREECIV\CWSDPMI -s-
    C:\FREECIV\VBECHECK --log C:\FREECIV\VBE800.LOG

    The upper half shows red/green/blue/white/black/yellow/cyan/magenta bars;
    the lower half is a black/white 16-pixel checkerboard. Press Q to return
    to the original text display with DOS screen contents preserved.
    --batch draws/reads back/restores without waiting, for repeated runs.
    Hardware/DPMI errors are written to the supplied log; success requires
    presentation/readback, original mode restoration and resource release.
    Repeat CWSDPMI -s- immediately before EACH no-paging application.

    Actual Pentium/16 MB/no-paging tests passed in both resolutions, using
    modes 0x111/0x114, pitches 1280/1600 and physical LFB 0xFD000000.
    Captured VGA output matched all 307200/480000 expected pixels with zero
    mismatches. Original text mode 3, keyboard Q, repeat launch and subsequent
    RTCHECK passed. No game resources, fonts, map, UI or gameplay are tested.
    Optional 1024x768 and real physical adapters are not certified.

    builds/phase4-dos/ holds the exact diagnostic/candidate, clean build and
    source distribution, host ASan/UBSan tests, actual DOS logs/screens,
    image checks and pixel-by-pixel verification. Its BUILDINFO.txt documents
    the discovered CWSDPMI unmap limitation and corrected resource lifecycle.

14. Primitive/font/dirty-render diagnostic (not the game):
    cd \FREECIV
    CWSDPMI -s-
    RNDCHECK 640 > RND640.LOG
    Press Q when the rendered pattern is visible to restore the DOS screen.
    Then repeat at the preferred resolution:
    CWSDPMI -s-
    RNDCHECK 800 > RND800.LOG

    Standard output MUST be redirected to a writable log as shown; the
    diagnostic sends hardware errors to the same destination. Inspect the log
    after returning to DOS. PASS initial readback, PASS local bytes=32,
    PASS repeated bytes=0, PASS coalesced bytes=12, PASS Q received and
    EXIT SUCCESS establish the diagnostic's measured outcomes. Readback alone
    does not replace inspection/capture of the actual VGA output.

    The pattern shows RGB bars, original printable-ASCII text at scale 2,
    clipped fill/lines and opaque/transparent/overlapping blits/icons.
    Required 640x480 and 800x600 outputs were captured and compared at every
    pixel against the native reference: 307200 and 480000 matching pixels,
    zero mismatches. Actual 16 MB/Pentium/CWSDPMI -s- tests also verify Q,
    original DOS text contents, repeat launch and post-render RTCHECK.

    A 4x4 update writes only 32 bytes; a repeated clean present writes zero.
    Dirty changes coalesce to a bounding rectangle, not an exact sparse list;
    separate distant updates may include unchanged pixels between them.
    Source build/test commands and embedded-font licensing are in DOS_PORT_SPEC.md.
    Exact artifacts, source/build/test logs, images, hashes and verification
    scripts are retained in builds/phase5-dos/. The unchanged Phase 4 VBECHECK
    and Phase 3 RTCHECK remain installed alongside the new diagnostic.

    These tests certify rendering foundations, NOT usable tileset loading,
    an interactive game HUD/map/event loop, DOS dialog/report integration,
    localized fonts, audio, complete gameplay or whole-game 16 MB memory fit.
    Normal FREECIV now opens the separately verified persistent pregame
    interface; that does not turn these component tests into full-game proof.

16. Persistent input/GUI diagnostic (uses the real production event loop):
    cd \FREECIV
    set HOME=C:\FREECIV
    set FREECIV_PATH=C:\FREECIV\GFX8
    CWSDPMI -s-
    INPUTCHK 640 > KBD640.LOG

    Before loading a driver, this explicitly reports keyboard-only input.
    Arrows move tile selection, Shift-arrows scroll and Ctrl-arrows/numeric
    keypad/WASD issue guarded orders. Selection/scrolling never move a unit
    locally. The fixture is not an established authoritative gameplay session,
    so game orders are visibly rejected. Enter/select, Tab/5 next, period wait,
    F done, E/Space end-turn and O overview have guarded command paths.
    Help/options/commands, list paging, text entry and safe quit are interactive.

    To enable optional tested mouse support, explicitly run:
    CTMOUSE
    CWSDPMI -s-
    INPUTCHK 800 > MOUSE800.LOG

    Left click selects map/UI items; right click opens commands. The client
    hides the driver cursor and draws a clipped software pointer. Latched
    INT33 press/release counters preserve quick clicks during idle. Actual
    tests receive nine 25 ms toolbar clicks and no repeat from a held button.
    Mouse list/text plus keyboard focus/edit/apply is verified separately.
    CTMOUSE is never loaded automatically. Keyboard-only remains supported.
    Keep its full source package/notices alongside redistributed driver files;
    runtime/cutemouse/README.txt records provenance and checksums.

    CWSDPMI -s-
    INPUTCHK --bridge > BRIDGE7.LOG
    This joins the actual local engine in pregame and services packets/timers/
    yields while the UI stays interactive. It does NOT call start_local_game
    or generate a map. Trace proves both client/engine establishment before
    clean disconnect; it must not inspect connection state after disconnect
    as though the session should still be established.

    All INPUTCHK modes require confirmed quit, restore BIOS text mode 3 and
    end with EXIT SUCCESS. Repeat the diagnostic and normal client; then:
    CWSDPMI -s-
    RTCHECK --batch --log C:\FREECIV\POSTINP.LOG
    Wait for EXIT SUCCESS before stopping QEMU or reading its disk.
    The unchanged older RTCHECK still prints its original readiness-gate note.
    That is historical diagnostic text, not the current production GUI status;
    use only its explicitly exercised runtime/engine service results.

    Verified bounds: FIFO64, eight-event acquisition/dispatch, packet budget16,
    500 ms timers; idle100000 us (~55-110 ms with BIOS clock granularity).
    10000 us truncates to zero in the tested DJGPP libc and must not be used.
    Acceptance rejects runaway loops with timers>=3, idle>=10 and
    ticks<=20*timers+128; acquired/dispatched event counts must match.
    Buffered BIOS Shift-Tab/Ctrl-Q/Alt-F4/modified arrows are normalized even
    after modifier release; NumLock digits remain orders.

    Actual input/bridge/display/teardown passes DOS6.22/Pentium/16 MB/-s-.
    Native real-engine/AI tests service actual editable modal widgets, but
    full joined-game/minimum-hardware AI timing/save/load remain unverified.
    builds/phase7-dos/ contains definitive logs/captures/BUILDINFO and verifiers.
    All 193 preceding regular files/attributes are preserved, including older
    diagnostics/assets/logs; the replaced client is archived as PHASE6.EXE.
    Root/partition/boot/floppy bytes are unchanged; FAT/partition checks pass.
    Stop for Phase 7 review. Do not start Phase 8 without explicit permission.
